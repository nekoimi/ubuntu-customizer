# 开发环境预装清单

适用系统：Ubuntu Server 24.04 LTS / amd64  
状态：已接入构建脚本；具体软件版本和配置文件在构建时记录，尚未执行完整 Linux 镜像构建与验证。

## 1. 已确认的预装范围

| 分类 | 预装内容 | 规则 |
|---|---|---|
| 编译工具 | `build-essential`、`pkg-config`、`cmake` | 提供 GCC / G++、make、基础开发头文件及常用构建工具 |
| Python | `python3`、`python3-venv`、`python3-pip`、`python3-dev` | 使用 Ubuntu 24.04 发行版维护的 Python，不另行替换系统解释器；开发头文件配合编译工具支持 Python 扩展构建 |
| Python 项目与工具管理 | `uv`、`uvx` | 构建时预装，`ubuntu` 用户登录后直接可执行；不要求预装 Rust |
| Python 包源 | pip 使用国内 PyPI 镜像 | 系统级配置随镜像交付，在首次启动前生效 |

Ubuntu 24.04 的默认 Python 系列为 3.12，具体补丁版本随所选 APT 软件包锁定，不额外安装其他 Python 主版本、PPA 或独立解释器。

## 2. 明确不预装的环境

- Node.js、npm、pnpm、Yarn 等 Node.js 运行时与包管理器。
- Java / OpenJDK / JRE / JDK，以及 Maven、Gradle 等 Java 构建工具。
- Go 工具链。
- Rust、rustup、Cargo 工具链。uv 使用预编译二进制，不为安装 uv 引入 Rust 编译环境。
- MySQL、MariaDB、PostgreSQL、Redis 等数据库或数据服务。
- Nginx、Apache 等 Web 服务。

这些规则描述主动预装范围。基础系统或已确认工具的正常运行依赖由 APT 解析，构建时核对实际依赖和软件清单，不强制卸载系统必要组件。

Docker Engine、CLI、containerd、Buildx 与 Compose 插件继续按主方案预装，不属于本节排除范围；采用每次构建时国内 Docker APT 仓库 stable 通道中可用的最新兼容稳定版本组合，并记录本次实际安装版本。

## 3. pip 国内源

国内源要求及具体镜像站已确定，采用清华 PyPI 镜像，通过构建配置 `python_package_index` 保存地址。

系统级配置建议写入 `/etc/pip.conf`：

```ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
```

- 保留 HTTPS 证书验证，不添加关闭验证的配置。
- 不额外配置海外 `extra-index-url`。
- 清理构建临时用户的 pip 配置，确保默认 `ubuntu` 用户不会被母机遗留配置覆盖。
- 用户后续仍可通过项目配置、环境变量或命令行自行覆盖默认源。

Ubuntu 的系统 Python 保留发行版的 externally-managed 机制。项目依赖安装到虚拟环境，默认不设置 `break-system-packages`，也不通过 `sudo pip install` 写入系统 Python。

## 4. uv 安装与默认配置

uv 在构建阶段安装预编译的 Linux x86_64 二进制，锁定版本和 SHA256，安装到所有用户可访问的位置，例如 `/usr/local/bin/uv` 和 `/usr/local/bin/uvx`。构建时完成实际下载与验证，首次启动时无需运行安装器、访问网络或编译 Rust。

uv 不依赖 pip 的配置文件，因此单独设置系统级 `/etc/uv/uv.toml`，使用与 pip 相同的清华国内 PyPI 镜像：

```toml
python-preference = "only-system"
python-downloads = "never"

[[index]]
name = "domestic"
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
```

默认使用已有的发行版 Python，不自动下载另一份解释器。具体配置项需在锁定的 uv 版本上验证。国内源地址在构建时从同一配置值生成，避免 pip 与 uv 配置不一致。

pip 与 uv 均只预配置包源，不预装未指定的第三方项目依赖；用户后续安装项目包时按需联网。完全离线安装系统不等于已经离线缓存全部 PyPI 软件包。

## 5. 验收要求

- `gcc`、`g++`、`make`、`pkg-config`、`cmake` 可用。
- `python3` 指向 Ubuntu 管理的系统解释器，`python3-dev` 与发行版版本匹配。
- `python3 -m venv` 可以创建包含 pip 的本地虚拟环境。
- `uv --version`、`uvx --version` 在 `ubuntu` 用户下可执行，无需首次启动安装。
- `uv venv --python /usr/bin/python3` 可使用系统 Python 离线创建虚拟环境，不触发解释器下载。
- pip 默认读取国内源；uv 的默认包索引也指向配置的国内源，HTTPS 验证正常。
- 最终软件清单不主动加入 Node.js、Java、Go、Rust 或数据库与 Web 服务。
- 默认 `ubuntu` 用户的家目录、缓存目录与配置属主保持 UID/GID `1000`，不残留构建用户个人配置。
