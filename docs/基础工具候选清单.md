# Ubuntu Server 基础工具清单

适用系统：Ubuntu Server 24.04 LTS / amd64  
状态：第 1 节已接入构建清单，第 2 节基础系统能力保留并验收；第 3 节仍为可选项。尚未执行完整 Linux 镜像构建。已确认的编译工具、Python 与 uv 范围见 [开发环境预装清单](开发环境预装清单.md)。

目标是断网时也能诊断网络、端口、DNS、磁盘、进程和系统性能。包名按 Ubuntu 的命名列出，构建时需检查所选国内源中的实际可用版本；基础系统已有的工具只需确认存在，不重复安装其他替代实现。

## 1. 已确认纳入基础预装的工具

| 分类 | 预装 APT 包 | 主要命令与用途 |
|---|---|---|
| 网卡、地址、路由、端口 | `iproute2`、`ethtool` | `ip` 查看地址、路由、邻居表；`ss` 查看监听端口和连接；`tc` 查看流量控制；`ethtool` 检查网卡协商速率、双工与链路 |
| 常用旧命令兼容 | `net-tools` | 提供 `ifconfig`、`netstat`、`route`、`arp`，方便沿用已有排障命令；日常优先使用 `ip`、`ss` |
| 连通性与 MTU | `iputils-ping`、`iputils-tracepath`、`iputils-arping` | `ping`、`tracepath`、`arping`，检查 IPv4/IPv6 连通性、路径 MTU 和局域网 ARP 响应 |
| 路由路径与丢包 | `traceroute`、`mtr-tiny` | `traceroute` 检查路径，`mtr` 持续观察各跳延迟和丢包；使用无图形依赖版本 |
| DNS | `dnsutils`、`bind9-host` | `dig`、`nslookup`、`host` 查询 A/AAAA/MX/TXT/SRV 等记录，并指定 DNS 服务器排查 |
| 端口探测与连接测试 | `netcat-openbsd`、`nmap`、`socat`、`inetutils-telnet` | `nc` 测试 TCP 连接，`nmap` 探测端口，`socat` 做临时转发和 Unix socket 调试，`telnet` 调试简单文本协议 |
| 抓包 | `tcpdump` | 抓取和保存流量，分析 DNS、TCP 握手、重传及指定端口通信 |
| 带宽与流量 | `iperf3`、`iftop`、`nload`、`vnstat` | `iperf3` 测试两台机器间吞吐；`iftop` 看连接流量；`nload` 看网卡速率；`vnstat` 可查看累计流量 |
| HTTP 与 TLS | `curl`、`wget`、`openssl`、`ca-certificates` | 测试 HTTP 状态、请求头、下载、TLS 握手和证书链，支持 HTTPS 请求 |
| 防火墙与连接跟踪 | `ufw`、`nftables`、`iptables`、`conntrack` | UFW 管理宿主入站策略；其余工具用于检查规则和 NAT 连接状态，便于诊断 Docker 网络 |
| 进程、资源、端口归属 | `procps`、`htop`、`lsof`、`psmisc`、`sysstat`、`iotop` | `ps`、`top`、`free`、`vmstat`、`watch`；`lsof`、`fuser` 查文件与端口占用；`iostat`、`pidstat`、`sar`、`iotop` 排查资源使用 |
| 磁盘、分区与硬件 | `util-linux`、`fdisk`、`parted`、`gdisk`、`smartmontools`、`nvme-cli`、`pciutils`、`usbutils`、`dmidecode` | `lsblk`、`blkid`、`findmnt`、`fdisk`；检查 GPT、SMART、NVMe 健康、PCI/USB 和硬件信息 |
| 文件系统与空间 | `e2fsprogs`、`dosfstools`、`xfsprogs`、`ncdu` | ext4、FAT、XFS 检查与维护；`ncdu` 定位目录占用；文件系统修复按是否挂载及工具要求执行 |
| 编辑、检索与结构化文本 | `vim`、`nano`、`less`、`file`、`tree`、`jq`、`ripgrep` | 编辑配置、查看日志、识别文件、搜索文本和解析 JSON |
| 归档与同步 | `tar`、`gzip`、`bzip2`、`xz-utils`、`zstd`、`zip`、`unzip`、`rsync` | 常见压缩包处理和目录同步 |
| 远程操作与会话 | `openssh-client`、`tmux` | `ssh`、`scp`、`sftp`、`ssh-keygen`；断开终端后保留运维会话 |
| 跨网络访问 | `tailscale` | 提供 `tailscale` 与 `tailscaled`；服务开机自启，安装后用户手动认证加入自己的网络 |
| 调试与变更对比 | `strace`、`diffutils`、`patch`、`git` | 排查进程系统调用、比较配置、应用补丁和管理代码 |
| 本地帮助 | `man-db`、`manpages`、`bash-completion` | 离线命令手册与 Bash 补全 |

`openssh-server` 是远程登录服务，是否启用及其认证策略见待确认清单 B3；`openssh-client` 仅提供主动连接其他机器所需的客户端工具。

## 2. 基础系统已有能力

以下能力应保留并验收，不把它们误认为需要额外安装的大型工具集合：

| 来源 | 常用命令 |
|---|---|
| coreutils、grep、sed、awk 等基础包 | `df`、`du`、`timeout`、`tail`、`sort`、`sha256sum`、`grep`、`sed`、`awk` |
| systemd | `systemctl`、`journalctl`、`timedatectl`、`hostnamectl`、`systemd-analyze` |
| Ubuntu 的名称解析组件 | `resolvectl` 查看本机 DNS 配置和缓存，具体可用性随 systemd-resolved 方案验证 |
| libc / 系统账户工具 | `getent hosts` 检查包含 hosts、DNS 在内的系统解析结果；`id` 检查账号与组 |
| APT / dpkg | `apt-cache`、`apt-mark`、`dpkg-query` 检查版本、依赖和软件包状态 |

安装 DNS 查询工具不意味着部署本地 DNS 服务器；保留 Ubuntu 正常解析机制，不因此替换网络管理方式。

## 3. 按需添加的工具

本节不随基础集合自动纳入，待有明确需求时添加。

| 场景 | 候选 APT 包 | 何时需要 |
|---|---|---|
| 深入分析抓包 | `tshark` | 希望在服务器上直接解码应用协议；基础方案也可将 tcpdump 的 pcap 文件拷到其他电脑用 Wireshark 分析 |
| HTTP 请求观察 | `ngrep` | 需要按内容匹配明文网络报文 |
| 二层邻居发现 | `lldpd`、`arp-scan` | 排查交换机端口、邻居设备和局域网地址 |
| 动态系统调用与内核分析 | `bpfcc-tools`、匹配内核的 `linux-tools-*` | 常规 strace / sysstat 无法解释的性能问题；需验证内核支持和工具版本 |
| 压力与 IO 基准 | `stress-ng`、`fio` | 新机器验机、性能基线和稳定性测试，按需手动运行 |
| 终端与交互协议自动化 | `screen`、`expect`、`picocom` | 需要兼容 screen 会话、自动交互或调试串口设备 |
| Samba / NFS 客户端 | `cifs-utils`、`nfs-common` | 需要挂载 Windows 共享或 NFS |

第一版通常不需要图形版 Wireshark、桌面组件或完整网络管理平台。

## 4. 安装和默认运行规则

- 工具在母镜像构建阶段安装，第一次启动前已经可用。
- Tailscale 已确认预装并启用 `tailscaled.service`；不在构建或安装时注册，不预置 Auth key、设备私钥或登录状态。用户进入系统后执行 `sudo tailscale up`，认证与后续连接需要联网；不阻塞离线安装和本地登录。具体规则见主方案第 6.2 节。
- 不因安装诊断工具自动更换现有网络管理器或 DNS 配置；防火墙按已确认的 UFW 基础策略预置，见 [构建与运行](构建与运行.md#ufw-防火墙预置)。
- 抓包、扫描和基准工具由用户按需运行，不开机自动执行。
- `iperf3` 默认不作为服务启动，不额外长期监听测试端口。
- `vnstat` 后台统计、`smartd`、sysstat 定时采集以及可选 `lldpd` 等服务是否启用，在构建时显式设置；未单独要求的采集或通告服务默认不启用。
- 包安装可能附带服务或定时器，构建时检查最终启用状态；不因加入命令行工具自动启用 nftables 服务、加载新规则或更改 Docker 网络规则。
- Ubuntu APT 使用已确定的国内镜像，工具版本进入软件清单。

## 5. 常见排障命令示例

```bash
# 地址、路由与监听端口
ip -br address
ip route
sudo ss -lntup
sudo lsof -iTCP:8080 -sTCP:LISTEN

# DNS：同时检查指定服务器响应和本机解析配置
dig example.com A
dig @223.5.5.5 example.com AAAA
resolvectl status
getent hosts example.com

# TCP 端口与 HTTP
nc -vz 192.168.1.10 22
curl -I https://example.com

# 路由与抓包
mtr -rw -c 20 223.5.5.5
sudo tcpdump -ni any port 53

# 系统资源与日志
iostat -xz 1
pidstat 1
sudo journalctl -u docker -n 100 --no-pager
```

示例 IP 和域名仅用于说明命令用法，实际排障时替换为目标地址。UDP、ICMP 和中间节点限速等情况需要结合协议判断，不能仅凭一个探测结果判定服务故障。
