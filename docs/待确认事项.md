## 2. 系统产品配置已全部确认

初始密码和清盘确认方式均已确定，不再保留产品配置待确认项。选盘倒计时结束只选定最大合格硬盘，随后等待一次明确确认，确认后才开始覆盖目标盘。

## 3. 已采用的常规配置

本节原建议值已由用户确认采用。更新策略也已确定为保留后台更新检查，关闭 SSH 登录提示，关闭自动安装及自动重启，由用户手动维护。

| 编号 | 配置项 | 已采用的配置 | 说明 |
|---|---|---|---|
| B1 | 国内软件镜像站 | Ubuntu 与 Docker APT 采用阿里云；pip 与 uv 的 PyPI 索引采用清华镜像 | 通过构建配置保存，不配置 Docker 镜像加速 |
| B2 | 额外卸载的软件 | 首版只明确移除 Snap，保留其他 Ubuntu Server 标准组件 | 不额外批量卸载软件 |
| B3 | SSH 登录方式 | 启用 OpenSSH，允许 `ubuntu` 用预设密码登录，端口 22；root 登录保持禁止 | 不要求安装时输入公钥 |
| B4 | 网络方式与主机名 | 以太网 DHCP，默认不询问网络参数；按安装生成主机名，如 `ubuntu-<机器标识短串>` | 安装器自动生成，无默认必填的网络配置步骤 |
| B5 | 磁盘布局与交换空间 | GPT + BIOS Boot 分区 + EFI 系统分区 + ext4 根分区，安装时扩容；2 GiB 交换文件 | 不启用 LVM、加密或独立数据分区 |
| B6 | Docker 使用权限与数据 | `ubuntu` 通过 sudo 管理 Docker，数据目录沿用 `/var/lib/docker`，配置日志轮转 | 不把 `ubuntu` 加入 docker 组 |
| B7 | 离线预置业务内容 | 正式镜像只预装工具与 Docker，不预置业务容器或数据；测试镜像单独准备离线验收用容器 | 不把验收容器留在正式母镜像中 |
| B8 | 系统公共配置 | 上海时区；默认 `en_US.UTF-8`，预留中文 locale；保留后台更新检查，关闭 SSH 登录提示，关闭自动安装及自动重启 | 用户手动维护补丁，详见主方案第 6.1 节 |
| B9 | 安装结束行为 | 展示完成状态，提示拔出 U 盘后由用户重启 | 不自动重启 |

不需要再次讨论 Docker 镜像加速地址：当前明确不配置。

## 4. 构建和验收需要提供的条件

| 条件 | 当前建议 | 需要补充的信息 |
|---|---|---|
| 构建环境 | 可联网的 Ubuntu 22.04 / 24.04 x86_64 构建机器；已有服务器资源适合开始验证，也可使用 VMware Ubuntu 虚拟机 | 当前改为根目录 `build.sh` 手动构建，不通过 GitHub Runner；需安装依赖、准备本地密码配置并执行首次完整构建，详见 [构建与运行](构建与运行.md) |
| 验收设备与责任 | 已确定由用户自行安排虚拟机测试和实体机器 U 盘安装测试，覆盖已约定的 UEFI / BIOS 兼容范围 | 不要求在构建前提供具体设备型号；测试时记录虚拟机平台或实体硬件、启动模式、ISO 版本及结果，发现问题后结合日志排查 |
| 安装介质 | 已确定采用混合 ISO 直接整盘写入 U 盘，虚拟机直接挂载 ISO | Ventoy 不纳入首版适配和验收，不再作为待确认项 |

最小设备规格已移出待确认项。构建时记录 ISO 大小和解压镜像长度，安装时检查目标盘能否容纳实际镜像；这些检查不作为最低设备配置的兼容承诺。安装耗时按实际测试记录，不开展最低配置专项验收。

构建宿主不要求与目标系统版本一致。当前直接在 Ubuntu 构建机器运行命令行，GitHub workflow 暂缓接入。最终完整安装验收由用户完成，不把用户验收设备的准备作为生成待验收 ISO 的前置条件。

以下为工程实现选择，不需要用户逐项确认：

实现仍需遵守已确定的产品要求；工程选择不能改变 30 秒选盘、预设账号、国内源或首次开机直接可用等行为。
