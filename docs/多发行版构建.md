# Ubuntu / Debian 多发行版构建

首版目标为 Ubuntu Server 24.04（noble）和 Debian 13（trixie），仅 amd64、ext4、GPT、BIOS / UEFI，关闭 Secure Boot。构建宿主仍为 Ubuntu 22.04 / 24.04。

原 Ubuntu ISO 已有用户实机安装成功记录。本次重构后的两个 Profile 都需要重新完成 Linux 构建、KVM 安装、断开 ISO 后硬盘引导及实体机验收；单元测试和静态检查不代表这些验收已通过。

## 使用方式

首次升级先执行 `bash build.sh setup`，补装 Debian 签名密钥等构建依赖。保留 `config/local.env`，无需重新填写已有密码、构建代理和 ntfy Token。推荐新配置使用 `INITIAL_PASSWORD`，旧 `UBUNTU_INITIAL_PASSWORD` 仍兼容，前者优先；密码不写进 Profile 或公开清单。

```bash
bash build.sh check --profile profiles/ubuntu-server.json
bash build.sh build --profile profiles/ubuntu-server.json

bash build.sh check --profile profiles/debian-server.json
bash build.sh build --profile profiles/debian-server.json
```

显式指定 `--profile` 时默认读取 `config/host.json`，也可用 `--config /path/to/host.json` 指定其他宿主配置。产物分别为：

```text
/srv/ubuntu-customizer/releases/<build-id>/ubuntu-custom-server.iso
/srv/ubuntu-customizer/releases/<build-id>/debian-custom-server.iso
```

Ubuntu 默认账号 `ubuntu`，Debian 默认账号 `debian`，均使用预设密码、UID/GID 1000，通过需要密码的 sudo 管理系统，不加入 Docker 组。Profile 的 `account.username` 可指定账号，安装成功提示及 ntfy 消息中的 SSH 命令跟随该账号。

KVM 入口保持不变，只替换 ISO 路径；不同发行版建议使用不同 `--state-dir`，详见 [Linux 虚拟机安装测试](Linux虚拟机安装测试.md)。

## 目录职责

```text
build.sh                         统一 CLI
image_builder/
  pipeline.py                    构建编排、命令执行、进度、报告
  core.py                        隔离检查、下载、宿主检查、磁盘工具
  packaging.py                   Alpine Live / initramfs / 混合 ISO
  config.py                      合并与验证公开配置
  distros/__init__.py             固定发行版注册表、debootstrap / guest 适配
distros/
  ubuntu/24.04/                  软件源、发行版包清单、默认值与检查
  debian/13/                     软件源、发行版包清单、默认值与检查
components/server/               共用软件包、系统配置、验收及引导脚本
profiles/                        目标系统、账号和功能集合
config/host.json                 宿主路径、资源、Alpine、uv、缓存
config/local.env                 私密设置，不入库
installer/                       共用选盘、清盘、写入、扩容和错误报告
scripts/                         CLI 兼容入口、宿主准备和交付工具
tests/                           原安全测试及多发行版行为测试
```

Profile 的 `mirrors` 可覆盖 `system_mirror`、`security_mirror`、`docker_mirror`、`python_index`，只接受 HTTPS，默认值来自各版本 `defaults.json`。共用包放在 `components/server/packages.txt`，专属包放在 `distros/<系统>/<版本>/packages.txt`。Debian 使用 `linux-image-amd64`、对应 firmware 包及 `bind9-dnsutils`，不安装 Ubuntu 元包。

首版 `components` 固定为 Docker、Tailscale、v2rayA、开发工具及运维预置的完整集合，不支持删除单项；构建前明确校验此限制。后续再拆分各组件的安装与检查依赖。当前不包含 CoreDNS。

Ubuntu / Debian 共用 systemd-networkd、systemd-resolved 和 Netplan DHCP 配置，Debian 屏蔽 `networking.service`，避免 ifupdown 同时管理网卡。APT、Docker、Tailscale 仓库按目标选择，保留签名验证。两者均使用 initramfs-tools 和 GRUB，当前共用 `bootloader.sh` 适配；其他家族需提供独立适配。

两者均预置 Docker 多平台构建命令与 ARM64 binfmt 启动注册；Ubuntu 安装 `qemu-user-static`，Debian 13 安装 `qemu-user`。安装后再按需创建带 v2rayA 代理的 BuildKit 构建器，操作与网络说明见 [Docker 多平台构建与代理](Docker多平台构建.md)。

缓存路径为 `<cache_dir>/<发行版>/<suite>/amd64/<仓库配置摘要>/apt/archives`，更换发行版、版本或仓库会使用独立缓存。原 `<cache_dir>/apt/archives` 保留，不自动迁移或删除。

## 兼容与安全

不带 `--profile` 的原命令继续使用 `config/build.json`、`config/packages.txt` 构建 Ubuntu，保留本地配置。显式 `--config config/build.json` 也只支持 Ubuntu，不能和 Debian Profile 混用。新构建推荐显式 Profile，此时不编辑旧包清单。

`scripts/build.py` 保留 CLI，实际 Python 代码在 `image_builder`；原 `customize.sh`、`check-guest.sh` 是 guest 兼容入口，不能在宿主直接执行。

新 manifest 使用 format 2，声明发行版、版本、账号、固定 `system.img.zst`、ext4 和 `debian-family-v1` 收尾协议。写盘前拒绝未知组合、任意 payload 路径和非法账号，收尾再核对目标系统 ID / VERSION_ID。format 1 的旧 Ubuntu 布局仍可识别，但不能用额外字段切换系统或文件名。每张 ISO 包含自己的安装器，不要手动替换旧介质中的 payload。

共用安全逻辑保持：构建隔离、排除安装介质与占用盘、明确清盘确认、旧签名清理、SHA256 写入回读、镜像范围外的末端 4 MiB 清理、分区节点身份校验及目标系统文件系统检查。新增系统不会绕过这些步骤。

为兼容既有脚本和设备，运行时 `/etc/ubuntu-customizer`、`/var/lib/ubuntu-customizer`、`ubuntu-ip-notify.*` 以及 Live 安装标记暂时保留。这些是项目内部接口，不代表目标只能是 Ubuntu。工程目录和 workflow 不自动改名；workflow 仍仅手动触发，默认 Ubuntu，不上传 ISO。
